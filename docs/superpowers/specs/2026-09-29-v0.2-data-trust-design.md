# v0.2 设计 — 数据可信（偿还技术债）

日期：2026-09-29
状态：已批准
上游文档：`ROADMAP.md` §v0.2

## 目标

让指标 Tab 的每个数字均可追溯到一次真实推理，UI 无预置假数据；打通流式输出链路。

## 范围（5 项）

1. 流式输出（JNI 回调 + 打字机 UI + 可中断）
2. 真实 ITL 序列与分位数（P50/P90/P99，替换 `avg × 1.2` 估算）
3. 调试日志收敛（编译期宏，默认关闭）
4. 功耗图假数据移除（换 v0.3 待接入占位）
5. 接受率假数据移除（删除 `getAcceptanceRate()`）

不在本版范围：功耗/温度真实采集（v0.3）、KV cache 持久化（v0.4）、推测解码实现（v0.5）。同步 `generate()`/`nativeGenerate` 保留不动（v0.3 自动化 harness 依赖）。

## ① 流式输出架构

```
HomeScreen「开始推理」→ BenchmarkViewModel.runBenchmark
  → NativeEngine.generateStream(prompt, maxTokens, StreamListener)
    → JNI nativeGenerateStream(jstring prompt, jint max, jobject listener)
      → GgmlBackend 生成循环（同步运行于 JNI 调用线程，即 Kotlin Dispatchers.Default）
        每采样 1 token → 用 JNI 入口传入的 JNIEnv 直接回调 listener.onToken(piece, index)
        循环结束      → listener.onDone(resultJson) → DeleteGlobalRef
        （调用线程本就附属于 JVM，无需 AttachCurrentThread；若未来生成移至
         native 自建线程，才需要 attach/detach）
  Kotlin onToken → Handler(Looper.getMainLooper()).post { uiState.generatedText += piece }
  Kotlin onDone  → 解析指标 JSON → uiState.result / uiState.isRunning=false
```

设计要点：
- 回调对象通过 `NewGlobalRef` 持有；`nativeGenerateStream` 同步阻塞直到生成结束，生命周期边界清晰（一次调用 = 一次 attach/detach）
- `KotlinListener` 方法签名（`GetMethodID` 查找）：`onToken(String, int)`、`onDone(String)`
- 中断：新增 `nativeCancel()` → `g_backend->cancel()`；生成循环每轮检查 `cancelled`（现有代码已具备）。UI 在 `isRunning` 时"开始推理"按钮变为"停止"
- Compose 状态写入统一 post 到主线程，避免跨线程改 snapshot state

## ② 真实 ITL 序列与分位数

**C++（`ggml_backend.cpp` 同步与流式两条路径共用同一计时逻辑）：**
- `GenerateResult`（types.h）新增：
  - `std::vector<double> token_timestamps_ms` — 每个 token 生成时刻（相对 `gen_start`）
  - `float itl_p50_ms, itl_p90_ms` — 与已有 `itl_avg_ms / itl_p99_ms` 并列
- 生成结束时：相邻时间戳差值序列 → 排序取 **nearest-rank** 分位数（`idx = ceil(q * n) - 1`，n=0 时全 0）
- 流式路径在 `onDone` JSON 中携带同样指标

**JNI（`edgepilot_jni.cpp`）：**
- `nativeGenerate` 与流式 `onDone` 输出统一 JSON：
  `text, total_tokens, tokens_per_sec, ttft_ms, total_time_ms, itl_avg_ms, itl_p50_ms, itl_p90_ms, itl_p99_ms, itl_series:[double...]`
- 引入 `json_escape()`：处理 `"` `\` `\n` `\r` `\t` 及 `< 0x20` 控制字符（`\uXXXX`），替换现有手写转义（现版本遇 `\r` 等会产出非法 JSON）

**Kotlin：**
- `GenerateOutput` 增加 `itlAvgMs/itlP50Ms/itlP90Ms/itlP99Ms/itlSeries: List<Double>`
- `BenchmarkViewModel`：直接使用 native 分位数；**删除 `itlAvg` 计算与 `avg × 1.2` 估算**
- `MetricsScreen`：ITL 卡片显示 avg + P50/P90/P99 三个真实值
- `TokenTimeChart(series, ttft)`：首柱 = TTFT，其后每柱 = 一个 ITL，全部来自真实数据

**接受率：**
- 删除 `NativeEngine.getAcceptanceRate()`（全仓库无调用方则直接删；有调用方则一并移除调用点）
- `BenchmarkResult.acceptanceRate` 保留字段但恒为 0（UI 已按 `>0` 隐藏），v0.5 接真实统计

## ③ 日志收敛

- 新建 `core/include/edgepilot/common/log.h`：
  ```cpp
  #ifdef EP_LOGGING
    #define EP_LOGD/I/W(...) ep_log_impl(级别, __VA_ARGS__)  // 非 Android 退化为 fprintf(stderr)
  #else
    #define EP_LOGD/I/W(...) ((void)0)
  #endif
  #define EP_LOGE(...) ep_log_impl(ANDROID_LOG_ERROR, __VA_ARGS__)  // 恒开启，不受开关裁剪
  ```
- `core/CMakeLists.txt`：`option(EP_LOGGING "enable verbose engine logging" OFF)`，开启时 `target_compile_definitions(... PRIVATE EP_LOGGING)`
- 替换 `ggml_backend.cpp` 4 处裸 `__android_log_print("EP", …)`；`edgepilot_jni.cpp` 的 `LOGI/LOGE` 宏改为引用 log.h
- 错误路径日志（LOGE 级别）默认保留，不受开关裁剪

## ④ 功耗图占位

- `PowerChart` 移除假 `data` 与基准线，改为占位卡：标题 "Power Consumption"，正文"真机功耗数据 · v0.3 接入"，Canvas 仅画空网格轴
- 预留入参 `powerSeries: List<Float>? = null`：非空时渲染真实曲线（v0.3 直接接线）

## ⑤ 验证与测试

无设备侧单测框架，验证以模拟器构建运行 + 日志断言为准：
1. 打字机：生成中 `generatedText` 逐 token 增长（UI 可见）
2. 可中断：生成中点击停止，循环退出、状态复位、无崩溃
3. 图表：`TokenTimeChart` 柱数 == `total_tokens`（1 根 TTFT + n-1 根 ITL）；`itl_series.size == total_tokens - 1` 由 Kotlin 校验，不符则 log 告警
4. 分位数：P99 ≥ P90 ≥ P50 ≥ 0，且不再等于 `avg × 1.2`（同一结果上肉眼可辨）
5. 日志：默认构建 logcat 无 "EP" 调试行；`-DEP_LOGGING=ON` 重新构建后出现
6. JSON：含换行/引号的生成文本不再破坏解析（用会输出多行文本的 prompt 验证）
