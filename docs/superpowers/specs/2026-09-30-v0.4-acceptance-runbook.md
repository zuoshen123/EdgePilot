# v0.4 真机验收 runbook（V1–V5）

配套 spec：`2026-09-30-v0.4-kv-cache-design.md`（§5.1/§5.2/§2.3/§6）。Locale/单位口径沿用 v0.3 runbook。
红线：任何不可用通道=空值/如实 note，不得手工补 0；两态（PASS/REJECTED）留档缺一不可。

## 0. 前置

1. 设备：arm64-v8a 真机（骁龙优先）；**Mock 环境（native 库缺失）下 V1/V2/V3 全部单元如实 ERROR，不构成验收数据**。
2. 模型推送（三处路径常量默认同一文件，改动需同改：`Recovery.kt:14` / `HomeScreen.kt:30` / `BaselineScreen.kt:34`）：
   ```bash
   adb push models/tinyllama-1.1b-chat-v1.0.Q4_K_M.gguf /data/local/tmp/tinyllama.gguf
   adb shell run-as com.edgepilot sh -c 'mkdir -p files/models && cat /data/local/tmp/tinyllama.gguf > files/models/tinyllama.gguf'
   ```
3. 构建带日志宏（V4 核对 `nativeInit` 行必需）：`./gradlew :app:assembleDebug -PepLogging=true`。
4. 串行铁律：矩阵/会话矩阵/量化对比/adb 恢复通道**共用一个引擎，一次只跑一个**；跑 V3 通道期间不要在 UI 点加载/推理。V3 的每次导出会覆写同名 `replay_baseline.txt`——严格按步骤顺序，勿在中途改档名重放。
5. 基线 Tab 顶部能力徽标先核对（功耗/温度/内存三通道 ✓/⚠）：⚠ 通道在 CSV 里是空列，V1/V2 判据不依赖它们（TTFT/bytes 均在）。

## V1 — 会话 TTFT 降幅（spec §5.1）

1. 基线 Tab →「跑会话矩阵（cache on/off×3轮）」（推荐线程，maxTokens 默认 128）。
2. `adb pull "<界面提示目录>/session.csv" .`
3. 对 中/长 桶每一对（同 turn）：`降幅 = (off.Rn.ttft − on.Rn.ttft) / off.Rn.ttft`，记录降幅表；**判据：R2/R3 平均降幅 ≥ 0.70**。短桶只记录不设门槛。
4. 附注：`cache_hit` 列是声明式标记（on 模式 R2/R3=1），非实测命中计数；`threads` 列 0=推荐档。

## V2 — KV 量化内存降幅（spec §5.2）

1. 基线 Tab →「量化对比（F16/Q8V8/Q8V4）」（贪心 32 tok，逐档重建）。
2. 取 `quant.csv`：**判据 = `1 − used_bytes(bits=4)/used_bytes(bits=16) ≥ 0.40`**（字节口径按 `getKVCacheInfo` 实算，非理论式）。
3. PSS 列（`pss_peak_mb`）**只如实报告**，不设门槛；空值=该通道不可用（对照徽标），不伪造。
4. 降档设备注记：若某档 `n_ctx < 4096`（预算自动降档），该行 `prefill_target_chars` 对应半量重试文本（`note=半量重试(3×LONG)`、`retried=1`）——**used_bytes 对比在此设备依然有效**（按实际 ctx 计），V2 判据照跑。
5. 目录无 `meta.json`：出处即 CSV 每行（run_ts/device/soc）。

## V3 — 跨进程会话恢复（spec §2.3）

1. 导出：
   ```bash
   adb shell am start -n com.edgepilot/.MainActivity --es ep_session_save rec1
   ```
   等 `files/recovery/session_export_result.txt` = `EXPORTED`（贪心三轮+存档，探针不入档）。
2. 冷杀再恢复（**判据限定：force-stop 后首个 load 才算跨进程恢复；同进程不 release 再 load 走 fast-path 复用，不构成冷恢复场景**）：
   ```bash
   adb shell am force-stop com.edgepilot
   adb shell am start -n com.edgepilot/.MainActivity --es ep_session_load rec1
   ```
   `session_recover_result.txt` 须 `PASS: 贪心 32 tok 逐字一致`。
3. 拒绝路径（两态都要留档）：
   ```bash
   # 存档两文件在应用内部 files/ 目录（外部 cat 不可见，用 run-as 取回改再推回）
   adb shell run-as com.edgepilot cat files/rec1.kvdat.json > rec1.kvdat.json
   # 篡改其一 → REJECTED 于对应校验段；另一分支用同样方法改 model_size
   # （model_path 段与 model_size 段是两条独立拒绝分支，可分别演示）
   adb shell run-as com.edgepilot sh -c 'cat > files/rec1.kvdat.json' < rec1.kvdat.json
   adb shell am force-stop com.edgepilot
   adb shell am start -n com.edgepilot/.MainActivity --es ep_session_load rec1
   ```
   结果文件须 `REJECTED: <具体校验段与原因>`；**MISMATCH** 出现时看 `mismatch_actual.txt`/`mismatch_expected.txt` 全长留档（不重试、不掩盖）。
4. 通道日志：`adb logcat -s EdgePilotRecovery`（通道完成后引擎 release=会话终结，UI 旗标自动复位属预期）。

## V4 — 推荐卡片与应用链（spec §6）

1. 未加载态：卡片三行=Context/线程/KV 档 + note「模型未加载：KV 预算未校验」——**预载 ctx=4096 是预测值（设计使然）**，不作判据。
2. 加载模型后卡片刷新为实态行：`KV 预估 xMB / 预算 yMB（可用×0.55）`；若显红行「当前 KV 超出内存预算」，只作警示记录，不断言引擎选档（加载时逐档选择，卡片只述即时事实）。
3. 点「应用」→ 回模型卡重新加载 → 判据 = **同一次重载之后**的卡片 vs 同一次重载后的 logcat：
   ```bash
   adb logcat -s EP | grep nativeInit   # 行内 threads/kv 应等于卡片 threads/kv_bits
   ```
   （预载卡片显示的 4096 与重载后 logcat 不一致不算失败——那正是预算降档在 loadModel 生效的证据，另行记录。）

## V5 — 贪心跨档一致率（spec §5.2 附带）

1. 取 V2 同目录 `quant_tokens_16.txt` vs `quant_tokens_4.txt`。
